12. Naming Conventions

All new class names, IDs, and data attributes should use camelCase — no BEM-style double dashes, no snake_case, no ad hoc abbreviations. Component + variant reads as one word, so related classes sort and scan together (e.g. btnPrimary, btnConfirm, btnDanger instead of btn--primary, btn--confirm, btn--danger).

Component Avoid Use instead
Button variant .btn--confirm .btnConfirm
Badge variant .badge--danger .badgeDanger
Slot state .slot--selected .slotSelected
Element ID #page-header #pageHeader
Data attribute data-is-active data-isActive

Existing components in this guide still use the original btn--variant pattern for reference — new components added to the system should follow the camelCase convention above so naming stays consistent going forward.
